# AI Travel Guide — Claude Code guide

SwiftUI iOS app that delivers AI-generated walking tours. Location feeds MapKit for POI discovery. Guide text (narration, chat) is generated by one of three backends chosen by `GuideRouter`: Claude API (user-supplied key), Apple's on-device Foundation Models, or bundled canned text. `SpeechService` reads responses aloud. Curated tour templates exist for Milan and Munich; AI-generated or MapKit tours cover anywhere else.

**Launch plan:** US App Store only, launch cities **NYC, Munich, Milan and Rome**. Languages per city: NYC en; Munich en + de; Milan en + de + it; Rome en + it + de (Rome languages assumed, confirm). Knowledge lives in a bundled per-city content pack; the on-device model retrieves and phrases it rather than recalling facts.

**Signature feature:** an ambient "walk mode" — the guide runs in the background while the user walks and speaks up (audio, via AirPods or speaker) when something worth sharing is nearby. See "Ambient guide mode".


## Revised architecture plan

Goal: a consumer-ready app where a small on-device model does location-aware UX, language output and Q&A, while **facts come from a curated, bundled city content pack**. Claude is an optional online tier and the offline content-build tool, not a launch dependency.

### Principles
- **The model retrieves and phrases; it does not remember.** Every factual claim in narration or chat should trace to a pack entry.
- **Deterministic routing.** Stop selection and ordering use code (MapKit distances, themes, time budget, existing `optimizeStopOrder`), not the LLM.
- **One service per concern.** New work goes in new services, not in `TourGuideService`.
- **Per-language content is authored at build time**, not translated at runtime.
- **Volatile data stays live** (hours, closures, prices); the pack holds durable content only.

### Model tiers (no user-supplied API keys in the consumer app)

Users are never asked for an API key. Cost is paid once at build time (Claude writes the packs), not per user.

| Tier | Who | What runs | Cost |
|---|---|---|---|
| A. Pre-written pack | Every iPhone | Narration, hooks and stories written at build time (per language, per persona), read by TTS. Questions answered by pack search (keyword/embedding match), returning the matching facts. No runtime LLM. | Free |
| B. On-device model | iPhone 15 Pro+ with Apple Intelligence | Foundation Models: live phrasing, follow-ups grounded via tool calling over the pack, parsing tour requests (`@Generable`). Offline and private. | Free |
| B+. Apple Private Cloud Compute | Same devices | Heavier questions via the same Foundation Models API. Announced as free for developers under ~2M first-time downloads. **Verify** task routing, limits and availability before relying on it. | Free under threshold |
| C. Own Claude proxy (optional, later) | Paid plan | Backend holds the key; auth + rate limits; open-ended questions beyond the pack. | Per use |

Rules that follow:
- `GuideRouter` order becomes: Tier C (if enabled and entitled) → Tier B/B+ → Tier A. Replace the "canned" backend with pack search (Tier A).
- Hide the "paste your Claude key" section from consumer builds (keep as a debug-only option). Never ship a key in the binary.
- Avoid free hosted APIs (Gemini free tier, Hugging Face inference, OpenRouter free models) as a core dependency: limits and terms can change and they still need a proxy. Bundling an open-weight model (Core AI/MLX/llama.cpp) only if Apple's model proves too weak for a specific task or older devices must be covered (1–2.5 GB on-demand download).
- Pre-written narration must exist for every entry × language × persona used in walk mode; Tier A depends on it.

### Target components

1. **City content pack** — `Resources/Cities/<city>.json` (nyc, munich, later milan). Loaded by a new `CityPackService`.
   - Stop: id, coordinates, category, themes, duration, per-language `name`/`summary`/`facts[]`, `sources[]`, `lastVerified`.
   - Pack metadata: schema version, languages, clusters (walkable areas of 30–60 stops each).
   - Keeps existing `TourStop`/`HistoricalFact` shapes where possible so `Tour` and saved tours stay compatible.
2. **`CityKnowledgeService` (retrieval)** — given location, current stop, tour and question, returns the top-N pack entries. Start with nearest-stop plus keyword match over facts; add embeddings only if that proves insufficient. Used by `OnDeviceGuideService.ask` and `ClaudeAPIService.ask` so both are grounded the same way. Replaces the ad-hoc fact-stuffing in `StopChatSheet`.
3. **Router extension** — route tour generation and enrichment through `GuideRouter`. Curated cities: build tours from the pack deterministically, then have the selected backend write narration. Uncurated places: MapKit tour plus (optional) Claude.
4. **On-device hardening** — surface error kinds (unavailable, guardrail, context exceeded) instead of returning `nil` for all; stream output so narration can start early; reuse/prewarm sessions; apply `GuidePreferences.selectedPersona` fallback for parity with Claude; use `@Generable` for parsing requests ("2 hours, foodie, no stairs") into tour parameters; check `SystemLanguageModel` language support for each entry in `supportedLanguages` and fall back per language.
5. **Cloud tier for launch** — users will not have API keys. Choose one before public release: (a) on-device only for MVP, (b) backend proxy holding the key with auth and rate limits. No key ships in the app binary.
6. **Content pipeline (offline, not shipped)** — driven by `docs/content-pipeline-prompt.md` (the full research and drafting prompt). Drafts pack entries per cluster from Wikidata (CC0), official registers (NYC LPC/Open Data, Bavarian Denkmalliste, Milan/Lombardia open data), public-domain guidebooks as leads, and cross-checks; generates per-language text natively; records a license for every source; flags unsourced claims; queues sensitive or conflicting entries for human review. Sensitive topics are **included, tagged and separated** (base text stands alone; sensitive material lives in a separate addendum) so the user toggle and kids mode can exclude them; every sensitive entry gets mandatory human verification before shipping. Entry detail levels: `hook` (~6 s spoken), `nugget` (~25 s), `deep_dive` (~80 s, Tier 1 only), plus optional persona and kids variants (Tier 1 only). Text volume is small (a few MB per city); the real cost is human review time.

## Ambient guide mode (walk mode)

The user starts a session ("Wander mode"), pockets the phone, and the guide speaks up when something interesting is nearby. Works with or without an active tour.

### What already exists
`LocationManager`: background location (`allowsBackgroundLocationUpdates`, blue indicator), heading, `CLCircularRegion` monitoring for tour stops. `TourViewModel.checkProximityToDiscoveryPoints`: proximity trigger, but only for the current and next stop of an active tour. `SpeechService`: narration preload/cache and streaming TTS; `audio` and `location` background modes are enabled.

### Content tiers (in the city pack)
- **Tier 1: tour stops** — full facts, 30–60 per cluster.
- **Tier 2: ambient landmarks** — buildings, plaques, squares, 100–300 per cluster, each with a one-line `hook`, a 2–4 sentence `nugget`, coordinates, `interest` score (1–5), optional `bestTime`, per language. Only Tier 1–2 may trigger a voice interruption.
- **Tier 3: MapKit-only POIs** — never trigger speech; available for chat answers.

### Components (new, one service per concern)
- `AmbientGuideService` — session state machine (idle, listening, speaking, cooldown); owns start/stop of walk mode.
- `TriggerEngine` — **pure, unit-tested** logic deciding whether to speak. Inputs: location, course, speed, candidate entries, history, user settings. Output: an entry or nothing.
- `POIIndex` — in-memory spatial grid over the loaded pack for fast nearest-N queries.
- `GuideIntents` (App Intents target files) — `TellMeMoreIntent`, `AskGuideIntent`, `AppShortcutsProvider`; thin wrappers over `AmbientGuideService`.
- `AmbientDelivery` — plays the nugget through `SpeechService`, plus optional haptic/notification when the app is backgrounded and audio is off.

### Trigger rules (start here, tune on real walks)
- **Candidates:** entries within ~40–60 m, or ~120 m when walking toward them (approach vector from `CLLocation.course`).
- **Use movement course, not the compass,** to decide "ahead/behind": the phone is usually in a pocket and heading is unreliable. Keep `directionLabel` for when the phone is held.
- **Rank** by `interest` × proximity × theme match × time fit (e.g. Glockenspiel near 11:00), minus repetition.
- **Restraint is the product:** each entry speaks at most once per session; global cooldown (e.g. 90 s); interruption budget per hour set by a Chattiness setting (Quiet / Balanced / Talkative); never speak while other audio or a call is active; don't speak while the user is stationary in a queue or cafe unless it is Tier 1.
- **Two-step delivery:** a soft chime plus one-line hook ("That building on your left hid a printing press in 1925…"), then the full nugget only if the user taps, says "tell me more", or Chattiness is Talkative.
- **Hands-free "tell me more" via App Intents** (SiriKit is deprecated; App Intents is the only path):
  - `TellMeMoreIntent` — plays the full nugget for the last announced entry. App Shortcut phrases include the app name, e.g. "Tell me more, <AppName>", "What was that, <AppName>".
  - `AskGuideIntent` — takes a `String` question parameter; Siri prompts ("What would you like to know?"), listens, and passes the text to the same Q&A path as in-app chat.
  - Both set `openAppWhenRun = false` and read the running walk-mode session through a shared dependency (register the session with `AppDependencyManager`, or a shared singleton), so they know which entry was just announced.
  - Also expose the same intent as a Live Activity / Dynamic Island button, a Lock Screen / Control Center control, and an Action Button assignment. One intent, several triggers.
  - Answer delivery: return `.result(dialog:)` (Siri voice, most reliable) or speak through `SpeechService` in the persona voice. Test the second on a real device for audio-session conflicts with Siri.
  - Shortcut phrases must contain the app name, so keep it short and easy to say. Check Apple's current App Intents docs for iOS 27 Siri phrasing changes before relying on one-sentence free-form questions. Siri AI features were unavailable in the EU/China at launch (not an issue for a US-only release).
- **Follow-ups:** Q&A uses retrieval on the nearest entries; on-device model phrases the answer. Use Foundation Models tool calling (a `nearbyEntries` tool over `POIIndex`) so the model fetches grounded facts itself.

### Platform constraints
- iOS caps region monitoring at 20 per app: keep the 20 nearest entries as regions and refresh as the user moves, or use `CLMonitor`. Continuous updates with a coarser `distanceFilter` (25–30 m) and `.fitness` activity type keep battery reasonable.
- Reliable background triggers after the app is suspended need location authorization; When-In-Use plus active background session works while the session runs. Request Always only if testing shows missed triggers.
- App Review needs a clear purpose string for background location and audio: "audio guide that speaks while you walk".
- Test with Xcode GPX routes and a replay harness for `TriggerEngine` using recorded walks.

### Data licensing notes
Wikipedia/Wikidata text is CC BY-SA (attribution and share-alike apply); OpenStreetMap is ODbL. Do not scrape Apple Maps data into the pack; use MapKit live and store only original content. Show attribution in-app. Confirm terms with counsel before release.

## Sensitive content controls

Difficult history (Nazi and fascist eras, persecution and genocide, war and violent death, executions, slavery and colonialism, terrorism, major disasters) is **part of the content**, not omitted. Users control it; kids never get it.

- **Setting:** `GuidePreferences.Key.includeDifficultHistory` (Bool), shown in Settings as "Difficult history". Proposed default: **on** for adult tours; change if testing shows it jars in ambient walk mode.
- **Kids mode overrides:** when `isKidFriendly` is true, sensitive content is always off regardless of the toggle.
- **Content model (per entry):** `sensitivity` (none/medium/high), `sensitivity_tags`, `sensitive_only`, `kids_safe`, `framing_cue` (one-line gentle lead-in per language), and a `sensitive_addendum` (hook prefix, nugget, deep dive) kept separate from the base `text`. Facts carry `sensitive: true`. See `docs/content-pipeline-prompt.md`.
- **Behavior:**
  - Toggle off or kids mode: entries with `sensitive_only` are hidden (not triggered, not suggested, not in tours); other entries play the base text only. Example: Königsplatz keeps its architecture story, minus the Nazi-era addendum.
  - Toggle on: the guide speaks the `framing_cue` first, then the addendum. Walk mode delivers these calmly (no chime, short hook first, "tell me more" for the rest); places of active mourning or worship use `ambient_quiet`.
- **Enforcement points (all must filter, not just the UI):** `TriggerEngine` candidate selection; `CityKnowledgeService` retrieval for Q&A (kids mode and toggle-off must never retrieve sensitive facts); tour assembly (`TourIdeaService`); on-device and Claude prompts (add an explicit instruction when the toggle is off or kids mode is on); pre-generated narration selection in Tier A.
- **Testing:** unit tests that a kids-mode tour and a toggle-off tour of each pilot cluster contain zero `sensitive_only` entries and no addendum text.

## Tour generation outside walk mode (public tour-idea library)

Public city-tour suggestions (tourism boards, museum and municipal trails, Wikivoyage walks, public-domain guides, self-guided routes) feed tour generation for each city when the user builds a tour instead of using walk mode.

- **Offline build:** `docs/tour-ideas-prompt.md` produces `Resources/Cities/<city>_tour_ideas.json`: 15–30 tour ideas per city (themes, durations, audiences) written in our own words, each an ordered list of pack entry ids plus connective walking notes. Ideas are blended from at least three independent sources; stops missing from the pack go to a `missing_entries` list for the content pipeline.
- **Runtime (`TourIdeaService`, new):** given start location, time budget, theme, kids mode and difficult-history toggle, select the best-matching ideas, adapt to the user's start point (drop/reorder stops with the existing route optimization), then hand the selected pack entries to the model to write only the introduction and transitions. Facts come from pack entries.
- **Replaces** the current "ask Claude to invent stops, then geocode them" path (`generateAIDesignedTour`) for cities with a pack; that path stays for uncovered places.
- **Guard:** ideas never copy a single commercial tour's stop selection and order; sources and terms are recorded per idea.

## Monetization layers (post-MVP, design for now)

1. **Free core:** city packs with ambient walk mode and Tier A/B guide (see model tiers). Keep cost per user near zero.
2. **Premium (optional):** Tier C open-ended Claude questions via the proxy, extra cities/languages, offline downloads.
3. **Curated tours by certified guides (creator layer):** guides publish paid tours inside the app.
   - **Pilot:** "Walk with me through Rome" by Lauren Farley, a former Rome tour guide, as the first guide tour (Rome, en + it + de). Needs a contributor agreement (ownership, license grant, warranties). Her routes, stories and any recorded audio are hers; do not ingest any published text of hers without a license. Describe her credentials as she can document them ("former guide" unless she holds a current qualification).
   - **Format:** a guide tour is an additional pack using the same entry schema, plus `author` (guide id, name, credentials), `license`, `price_tier`, `languages`, and optional **recorded human audio** per entry (played instead of TTS; text kept for captions and the on-device Q&A).
   - **Playback:** the trigger engine runs the guide's route in "guided sequence" mode (ordered stops, custom trigger radii, guide-authored discovery points); ambient Tier 2 entries from the base pack can be blended in or turned off per tour.
   - **Q&A:** the on-device model answers from the guide's tour entries first, then the base city pack; it never answers as the guide or speaks in a cloned voice.
   - **Creator tool (later):** guide uploads notes/audio, picks stops on a map (coordinates validated against the sources in the content prompt), gets AI-drafted hooks/nuggets and translations for approval, and runs the same fact-check pass. Sensitive-site rules from the content prompt apply to guide content too.
   - **Commerce:** digital tours sold in-app use Apple in-app purchase (Apple's commission applies; check the App Store Small Business Program rate). Revenue share, payouts, and tax forms (US and foreign guides) handled by a payments provider on the web side. Verify current App Store rules on external payment links before designing checkout.
   - **Certification:** define what counts (as far as I know: Italy requires a state guide qualification; Germany has voluntary certifications such as the BVGD/IHK Gästeführer; NYC has a sightseeing guide license administered by the city). Verify each jurisdiction's rules before advertising "certified" and store credential type, issuer and check date per guide.
   - **Legal and risk:** contributor agreement (ownership, license grant, warranties, takedown), route safety disclaimers, moderation queue, content that overlaps in-copyright books/guides needs a license from the author.
   - **Schema hooks to add now (cheap):** `pack_id`, `pack_type` (`city|guide_tour`), `author`, `license`, `audio_url` per language on entries; nothing else needed until the creator layer is built.
4. **B2B/partnerships (later):** tourism boards, hotels, museums sponsoring or supplying packs; guide-booking leads for in-person tours.

## Swift conventions in this codebase

1. **`@MainActor` on ViewModels and UI-touching Services.**
2. **`ObservableObject` + `@Published`**, not `@Observable`. Don't mix styles.
3. **DI via `@StateObject` in `AITravelGuideApp` + `@EnvironmentObject` downstream.**
4. **`APIKeyManager.shared` is a singleton.** Don't DI it.
5. **Async/await for network calls.** No Combine in new code.
6. **One service per concern.** Don't grow `TourGuideService`.
7. **Backend choice goes through `GuideRouter`.** Don't branch on API-key presence at call sites.
8. **Foundation Models code stays behind `#if canImport(FoundationModels)` and `#available(iOS 26, *)`.**
9. **Seed/content data belongs in `Resources/` as JSON** (Swift-file seed data is legacy).
10. **Permission strings in `Info.plist`** are edited by hand or in Xcode.
